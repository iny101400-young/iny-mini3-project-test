# BuildWise Prototype v1 Decision Report

## 0. 문서 역할

이 문서는 Decision Report에 담을 내용의 원칙을 정리한다.

Decision Report의 최종 화면 구조와 읽는 순서는
`WIREFRAME_05_DECISION_REPORT.md`를 따른다.

- Decision 화면(`WIREFRAME_04_DECISION.md`)은
  전체 후보를 비교하고 탐색하는 작업 화면이다.
- Decision Report는
  결과를 읽고 회의·검토에 공유하기 위한 정리 화면이다.

따라서 Report에서는 전체 후보 비교표를 그대로 보여 주지 않고,
우선 검토할 후보를 Candidate Shortlist로 정리한다.

## 1. 한 줄 판단

사용자 조건을 바탕으로 현재 상태를 한 문장으로 요약한다.

Report에서는 한 줄 판단과 Recommended Direction을
Executive Summary로 묶어 가장 먼저 보여 준다.

가능한 표현:

- 기존 솔루션 활용 후보 있음
- 기존 솔루션 + 추가 확인 필요
- 현재 조건에서 후보 없음

"추가 개발 검토"는 현재 v1 데이터만으로 확정하지 않는다.

## 2. 입력 조건 요약

- 월 예산
- 출처 인용 필요 여부
- OCR 필요 여부

## 3. 판단 요약

반드시 보여 줄 값:

- 전체 비교 후보 수
- 예산 내 후보 수
- 모든 필수 조건이 확인된 후보 수
- 추가 확인이 필요한 후보 수

## 4. Recommended Direction

제품 하나를 단순 추천하는 것이 아니라,
현재 조건에서 가장 적절한 활용 방향을 설명한다.

예:

- 기존 SaaS 우선 검토
- 기존 SaaS 후보 검토 + 추가 확인
- 예산 조건 조정 후 재검토

현재 데이터에 없는 사실은 만들지 않는다.

Report에서는 Executive Summary 안에 포함한다.

## 5. Candidate Shortlist

Decision 화면의 전체 비교표를 그대로 복사하지 않는다.

실무자가 우선 검토할 후보를 읽기 쉽게 정리한다.

후보별 표시 항목:

- 제품명
- 가격
- 가격 원문
- 출처 인용 상태
- OCR 상태
- 현재 조건 결과
- 확인 필요 항목
- `detail_url`

임의의 추천 점수나 순위를 만들지 않는다.

후보는 아래 순서로 묶어 보여 줄 수 있다.

1. 모든 필수 조건이 확인된 후보
2. 추가 확인이 필요한 후보

한 줄 판단이 "현재 조건에서 후보 없음"이면
Candidate Shortlist를 표시하지 않는다.
빈 표나 대체 후보도 보여 주지 않는다.

## 6. Evidence

판단 근거를 다시 확인할 수 있도록 아래 항목을 명확하게 표시한다.

- 원문 출처
- 수집 시점
- 가격 원문
- 기능 확인 상태
- 현재 데이터 한계

EDA에서 실제 확인한 시장 참고 정보는
사실과 해석을 분리해서 사용할 수 있다.

### 현재 확인된 사실

- 정제 데이터 14개
- $0 이상 $10 미만 후보 8개
- Citation Yes 그룹 평균 8.46 USD
- Citation No 그룹 평균 20.75 USD
- No 그룹은 n=4이고 49 USD 값이 포함돼 평균에 크게 영향을 받을 수 있음

이 수치는 시장 전체가 아니라
현재 수집한 표본의 결과라는 점을 반드시 표시한다.

## 7. Next Action

실무자가 이 결과를 본 뒤
무엇을 추가 확인해야 하는지 정리한다.

예:

- 상세 요금제 확인
- 사용자 수 과금 확인
- 처리 한도 확인
- 조직 보안/데이터 정책 확인

실제 데이터에 없는 사항은 "추가 확인 필요"로만 표시한다.

## 8. 이 리포트의 목적

검색 결과를 나열하는 것이 아니라,

> "실무자가 다시 정리하지 않아도
> 현재 상태, 근거, 후보, 확인할 항목, 다음 액션을
> 한 화면에서 이해할 수 있게 만드는 것"

을 목표로 한다.

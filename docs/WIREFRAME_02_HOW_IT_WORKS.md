# BuildWise How it works Wireframe

## 1. 화면 목적

사용자가 BuildWise가 어떤 순서로 판단하는지
1분 안에 이해할 수 있게 한다.

단순 사용 방법 설명이 아니라,
BuildWise가 일반 AI 툴 추천 사이트와 어떻게 다른지도 설명해야 한다.

핵심 메시지:

> "제품을 먼저 고르는 것이 아니라,
> 우리 업무 조건을 먼저 정의한 뒤
> 시장 데이터와 비교하고,
> Gap과 근거를 확인해
> 실무자가 의사결정할 수 있는 상태로 정리한다."

## 2. Intro

제목:

> 어떤 AI를 쓸지 고르기 전에,
> 우리 업무에 무엇이 필요한지부터 정리합니다.

서브:

> BuildWise는
> 조건 정의 → 시장 비교 → Gap 확인 → Decision Report
> 순서로 판단을 구조화합니다.

## 3. Step 01 — 업무 조건 정의

제목:

> 01 우리 업무 조건을 먼저 정의합니다

설명:

현재 v1에서는 실제 데이터로 비교 가능한 항목만 사용한다.

입력 항목:

- 월 예산 (USD)
- 출처 인용 필요 여부
- OCR 필요 여부

현재 데이터로 검증할 수 없는 아래 항목은
v1 입력값으로 사용하지 않는다.

- 업무 목적
- 월 사용량
- 사용자 수
- 다중 PDF 비교

핵심:

> "필요한 조건을 먼저 정의해야
> 좋아 보이는 제품이 아니라
> 우리 상황에 맞는 후보를 찾을 수 있다."

## 4. Step 02 — 기존 AI 시장과 비교

제목:

> 02 같은 기준으로 기존 솔루션을 비교합니다

설명:

현재 정제된 PDF AI 데이터 14개를
동일한 조건으로 비교한다.

비교 기준:

- 가격
- 출처 인용 확인 상태
- OCR 확인 상태
- 원문 가격
- 원문 출처

중요:

기능 표시가 없다고
"미지원"으로 단정하지 않는다.

확인되지 않은 정보는
"확인 필요"로 남긴다.

## 5. Step 03 — Gap과 판단 근거 확인

제목:

> 03 맞는 것과 더 확인할 것을 나눕니다

표현 상태:

- ✓ 충족
- ? 확인 필요
- ! 예산 초과

설명:

각 후보를 단순 점수로 줄 세우지 않는다.

대신 아래 내용을 분리해서 보여 준다.

- 어떤 조건은 충족됐는지
- 어떤 조건은 확인이 필요한지
- 어떤 후보가 예산을 넘는지

핵심:

> "모르는 것을 없는 것처럼 판단하지 않는다."

## 6. Step 04 — Decision Report

제목:

> 04 검색 결과를 의사결정 가능한 리포트로 정리합니다

결과에 포함:

- Executive Summary (한 줄 판단 + Recommended Direction)
- 입력 조건
- 판단 숫자 요약
- What We Know / What We Need to Check
- Candidate Shortlist
- Evidence Summary
- Market Context
- Next Action
- Data Limit

핵심:

> "실무자가 다시 엑셀이나 문서로 정리하지 않아도
> 회의·검토에 바로 활용할 수 있는 상태를 만든다."

## 7. Before / After

| 왼쪽: 기존 방식 | 오른쪽: BuildWise |
| --- | --- |
| 검색 | 조건 입력 |
| → 제품별 기능 확인 | → 동일 기준 비교 |
| → 가격 다시 확인 | → 충족 / 확인 필요 구분 |
| → 비교표 작성 | → 근거 확인 |
| → 빠진 기능 다시 확인 | → Decision Report |
| → 구매/개발 논의 | |

중요:

실제 측정 전에는
시간 절감 수치나 퍼센트를 표시하지 않는다.

카피:

CTA:

- 조건 비교 시작

## 9. Layout 원칙

- 4단계를 한눈에 이어지는 흐름으로 보여 준다.
- 카드 4개를 단순 나열하는 것보다
  Process / Flow 느낌을 우선한다.
- Desktop에서는 가로 흐름 또는 세로 흐름 중
  정보 전달이 더 명확한 방식을 사용한다.
- HIMEC 사이트를 복제하지 않는다.
- White / Deep Navy / Blue 중심의
  엔지니어링 B2B 분위기를 유지한다.
- 장식보다 단계와 논리 구조가 먼저 보이게 한다.

## 10. 사용자가 이 화면을 보고 이해해야 하는 것

1. BuildWise가 제품 추천부터 시작하지 않는다는 점
2. 우리 업무 조건을 먼저 정의한다는 점
3. 같은 기준으로 시장을 비교한다는 점
4. 확인되지 않은 정보를 임의로 추측하지 않는다는 점
5. 최종적으로 Decision Report를 얻는다는 점

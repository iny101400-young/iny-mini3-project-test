# BuildWise Prototype v1 — IA & Design Direction

## 1. 제품 경험 원칙

BuildWise는 일반 AI 툴 추천 사이트처럼 보이면 안 된다.

핵심 경험:

- 제품 목록보다 "우리 상황에 대한 판단"을 먼저 보여 준다.
- 실무자가 다시 엑셀이나 문서로 정리하지 않아도 된다.
- 판단 결과와 근거가 한 흐름에서 연결된다.
- 확인되지 않은 정보는 임의로 추측하지 않는다.
- 실무자가 회의나 검토에 바로 가져갈 수 있는 결과물을 만든다.
- PDF 추천 서비스가 아니라 AI 도입 의사결정 지원 시스템으로 보여야 한다.

핵심 문장:

> "검색 결과를 주는 것이 아니라,
> 실무자가 바로 의사결정할 수 있는 상태로 정리한다."

## 2. 전체 페이지 구조

v1은 아래 5개 영역으로 구성한다.

### 0. Home / Landing

목적:

- BuildWise가 왜 필요한지 이해
- 단순 PDF 툴 추천 서비스가 아니라는 점 전달
- 비교 시작 CTA 제공

핵심 메시지:

> AI 활용의 차이는 '얼마나 많이 쓰느냐'가 아니라
> '우리에게 무엇이 필요한지 정확히 아느냐'에서 시작됩니다.
>
> 업무마다 흩어진 선택을 기준으로 만들고,
> 그 기준을 쌓아 전사적인 AI 활용 체계로 확장합니다.
>
> BuildWise는 그 판단을 돕습니다.

CTA:

- "우리 조건으로 비교하기"

현재 범위 안내:

- "PDF 문서 검토 업무부터 검증 중인 BuildWise Prototype v1"

### 1. How it works

목적:

사용자가 무엇을 입력하고 어떤 결과를 얻게 되는지
짧게 이해할 수 있게 한다.

4단계:

1. 01 업무 조건 정의
2. 02 기존 AI 시장과 비교
3. 03 Gap과 판단 근거 확인
4. 04 Decision Report 확인

핵심:

사용 방법 설명이면서 동시에
BuildWise의 제품 차별점을 설명해야 한다.

### 2. Compare

목적:

현재 v1 데이터로 실제 비교 가능한 조건만 입력한다.

입력:

- 월 예산 (USD)
- 출처 인용 필요 여부
- OCR 필요 여부

현재 데이터에 없는 아래 항목은
입력 항목으로 만들지 않는다.

- 업무 목적
- 월 사용량
- 사용자 수
- 다중 PDF 비교

CTA:

- "우리 조건으로 비교하기"

화면 하단에는 현재 데이터 한계를 짧게 표시한다.

### 3. Decision

목적:

제품 목록보다 먼저
"우리 상황에 대한 판단"을 보여 준다.

표시 순서:

1. 한 줄 판단
2. 입력 조건 요약
3. 후보 수 요약
4. Recommended Direction
5. Candidate Comparison
6. Gap / 추가 확인
7. Evidence
8. Next Action

판단 결과:

- 기존 솔루션 활용 후보 있음
- 기존 솔루션 + 추가 확인 필요
- 현재 조건에서 후보 없음
- 추가 개발 검토는 v1에서 확정하지 않음

### 4. Decision Report

목적:

실무자가 다시 정리하지 않아도
회의·검토에 가져갈 수 있는 최종 결과를 제공한다.

구성:

- Executive Summary
- 입력 조건
- 판단 숫자 요약
- What We Know / What We Need to Check
- Candidate Shortlist
- Evidence Summary
- Market Context
- Next Action
- Data Limit

Recommended Direction은 Executive Summary 안에 포함한다.

Report에서는 Decision 화면의 전체 비교표(Candidate Comparison)를
그대로 쓰지 않고, 우선 검토할 후보를 Candidate Shortlist로 정리한다.

최종 구조 기준은 `WIREFRAME_05_DECISION_REPORT.md`를 따른다.

현재 v1에서는 PDF 다운로드 기능을 아직 구현한다고 확정하지 않는다.
우선 웹에서 읽기 좋은 리포트 형태를 목표로 한다.

## 3. 사용자 흐름

```
Home
→ How it works
→ Compare
→ Decision
→ Decision Report
```

단, Home에서 바로 Compare로 이동할 수도 있게 한다.

제품 리스트부터 탐색하는 구조는 만들지 않는다.

## 4. Global Navigation

상단 Navigation 예시:

- BuildWise
- Home
- How it works
- Compare
- Evidence

오른쪽 CTA:

- "조건 비교 시작"

Evidence는 BuildWise의 핵심 차별점인
근거 추적성을 보여 주는 메뉴다.

현재 Prototype v1에서는 별도 Evidence 페이지를 만들지 않는다.

Navigation의 Evidence는 별도 페이지가 아니라
Home 화면의 Evidence Preview 영역으로 이동하는
섹션 앵커 역할을 한다.

향후 별도 Evidence 페이지는 확장 가능성으로만 남긴다.

## 5. Design Direction

HIMEC의 기업·엔지니어링 이미지와 자연스럽게 어울리는
B2B SaaS 스타일을 지향한다.

HIMEC 사이트를 그대로 복제하지 않는다.
독립적인 BuildWise 제품 디자인으로 만든다.

디자인 키워드:

- 신뢰
- 정밀함
- 엔지니어링
- 구조적
- 전문적
- 검증 가능
- 높은 정보 가독성

기본 방향:

- White 중심 배경
- Deep Navy 계열의 텍스트와 주요 영역
- Blue 계열의 Action / Highlight
- 넓은 여백
- 직선적이고 정돈된 Grid
- 과도한 장식이나 화려한 Gradient 최소화
- 카드보다 정보 위계와 표의 가독성을 우선

정확한 HIMEC 공식 브랜드 색상 HEX를
근거 없이 임의로 만들지 않는다.
현재는 색상 역할만 정의한다.

## 6. 상태 표현

사용자가 표를 2~3초 안에 스캔할 수 있게
상태를 시각적으로 명확히 구분한다.

상태:

- 충족
- 확인 필요
- 예산 초과

색상 역할 예시:

| 상태 | 색상 역할 |
| --- | --- |
| 충족 | 안정적인 Blue/Green 계열 |
| 확인 필요 | Amber 계열 |
| 예산 초과 | Red 계열 |

색상만으로 의미를 전달하지 않고
아이콘 + 텍스트를 함께 사용한다.

예:

- ✓ 충족
- ? 확인 필요
- ! 예산 초과

## 7. Candidate Card / Comparison 원칙

제품 하나를 볼 때
다음 정보를 빠르게 스캔할 수 있어야 한다.

- 제품명
- 가격
- 가격 원문
- Citation 확인 상태
- OCR 확인 상태
- 현재 조건 충족 여부
- 추가 확인 필요 항목
- 공식/원문 근거 링크

제품 설명을 길게 읽게 하지 않는다.

아래 핵심 질문에 바로 답해야 한다.

- "우리 조건에 맞는가?"
- "무엇이 확인됐는가?"
- "무엇을 더 확인해야 하는가?"
- "근거는 어디인가?"

## 8. Evidence UI 원칙

BuildWise의 차별점 중 하나는
추천 결과보다 판단 근거를 확인할 수 있다는 것이다.

Evidence 영역에는 아래 항목을 명확하게 표시한다.

- 원문 URL
- 수집 시점
- 가격 원문
- 기능 확인 상태
- 데이터 한계
- 현재 표본 기반 EDA 참고

### 현재 EDA 사실

- 정제 데이터 14개
- $0 이상 $10 미만 후보 8개
- Citation Yes 그룹 평균 8.46 USD
- Citation No 그룹 평균 20.75 USD
- Citation No 그룹 n=4
- 해당 그룹에 49 USD 값 포함

이 데이터는 "시장 전체"가 아니라
현재 수집한 표본의 결과라고 반드시 표시한다.

## 9. Responsive 원칙

Desktop 우선으로 설계하되
모바일에서도 핵심 정보는 확인 가능해야 한다.

특히 Candidate Comparison 표는
모바일에서 지나치게 축소하지 않고,
아래 방식 중 하나로 처리할 수 있게 설계한다.

- 카드 전환
- 중요한 열 우선 표시

현재 단계에서는 구현 방식까지 확정하지 않는다.

## 10. v1에서 하지 않는 것

- 로그인
- 회원가입
- 결제
- 관리자 페이지
- 음성 AI 비교
- 여러 AI 카테고리
- 가짜 AI 채팅
- 실제 데이터에 없는 추천 점수
- 임의의 시장점유율
- 검증되지 않은 "최적" 표현
- 실제 측정 전 시간 절감 수치 표시

## 11. 프로토타입에서 검증할 UX 질문

향후 사용성 테스트에서 확인할 것:

1. 사용자는 30초 안에 입력을 완료할 수 있는가?
2. 결과 화면에서 가장 먼저 결론을 이해할 수 있는가?
3. 후보끼리 차이를 빠르게 비교할 수 있는가?
4. 왜 이런 판단이 나왔는지 근거를 확인할 수 있는가?
5. 다음에 무엇을 해야 할지 이해할 수 있는가?
6. 결과를 별도로 다시 정리하지 않고 회의·검토에 활용할 수 있는가?

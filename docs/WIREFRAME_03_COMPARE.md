# BuildWise Compare Wireframe

## 1. 화면 목적

사용자가 30초 안에
현재 v1에서 실제 비교 가능한 조건을 입력하고
Decision 화면으로 넘어갈 수 있게 한다.

입력 과정은 짧고 명확해야 하며,
각 항목을 왜 묻는지 사용자가 이해할 수 있어야 한다.

## 2. Intro

제목:

> 우리 업무에 필요한 조건을 입력해 주세요.

서브:

> 현재 Prototype v1은
> PDF 문서 검토 AI를
> 예산, 출처 인용, OCR 기준으로 비교합니다.
>
> 현재 데이터로 검증할 수 없는 조건은
> 입력값으로 받지 않습니다.

## 3. 입력 01 — 월 예산

라벨:

- 월 예산

입력 단위:

- USD

입력 예시:

- 10

도움말:

> 현재 데이터의 유료 요금제 시작가와 비교합니다.

주의 안내:

- 일부 가격은 연간 결제 기준 월 환산 금액일 수 있음
- 일부 가격은 사용자당 요금일 수 있음
- 따라서 최종 도입 전 상세 요금제 확인이 필요함

UI 원칙:

- 숫자 입력
- $ 단위를 명확하게 표시
- 0보다 큰 값만 입력 가능
- 너무 복잡한 슬라이더보다 직접 입력 우선

## 4. 입력 02 — 출처 인용

질문:

> 답변에 출처 인용 기능이 반드시 필요한가요?

선택:

- 필요함
- 상관없음

기본 선택값은 두지 않는다.
사용자가 둘 중 하나를 직접 선택해야 한다.

상관없음:

해당 기능이 필요 없다는 뜻이 아니라,
현재 비교에서 필수 조건으로 사용하지 않는다는 뜻.

도움말:

> 출처 인용은
> AI 답변이 어떤 문서 내용에 근거했는지
> 확인하는 데 사용하는 기능입니다.

판단 기준:

- 필요함 → `citation == Yes` 후보를 명확한 충족으로 판단
- 상관없음 → citation 여부를 필수 조건으로 사용하지 않음

중요:

`citation == No`는
"미지원"으로 단정하지 않는다.
현재 데이터에서 확인되지 않은 상태로 처리한다.

## 5. 입력 03 — OCR

질문:

> 스캔된 PDF나 이미지 기반 문서를 읽어야 하나요?

선택:

- 필요함
- 상관없음

기본 선택값은 두지 않는다.
사용자가 둘 중 하나를 직접 선택해야 한다.

상관없음:

해당 기능이 필요 없다는 뜻이 아니라,
현재 비교에서 필수 조건으로 사용하지 않는다는 뜻.

도움말:

> OCR은 스캔된 문서나 이미지 속 글자를
> 텍스트로 인식하는 기능입니다.

판단 기준:

- 필요함 → `ocr_raw == "Scanned PDF support"`이면 충족
- 상관없음 → OCR 여부를 필수 조건으로 사용하지 않음

빈칸은
"미지원"이 아니라
현재 수집 데이터에서 확인 필요로 처리한다.

## 6. 입력 요약 Preview

사용자가 선택한 조건을
CTA 바로 위에서 한 번 확인할 수 있게 한다.

예:

| 조건 | 입력값 |
| --- | --- |
| 월 예산 | $10 이하 |
| 출처 인용 | 필요함 |
| OCR | 필요함 |

이 영역은 사용자가
"내가 어떤 조건으로 비교하는지"를
바로 이해할 수 있게 한다.

## 7. Primary CTA

버튼:

- 우리 조건으로 비교하기

CTA 실행 후:

Decision 화면으로 이동한다.

버튼을 누르기 전
필수 입력값이 빠졌다면
해당 항목만 명확하게 안내한다.

실행 조건:

아래 세 조건이 모두 입력되어야
"우리 조건으로 비교하기" 버튼을 실행할 수 있다.

- 월 예산 입력
- 출처 인용 선택
- OCR 선택

사용자가 입력하지 않은 값을
자동으로 "상관없음"으로 처리하지 않는다.

이유:

두 기능은 후보 판단에 직접 영향을 주는 요구조건이므로
사용자의 명시적인 선택을 받기 위함이다.

## 8. Data Limit 안내

입력 화면 하단에
너무 길지 않은 안내를 표시한다.

예시 방향:

> "현재 Prototype v1은
> 공개된 가격·출처 인용·OCR 정보를 기준으로 비교합니다.
> 표시되지 않은 기능은 미지원으로 단정하지 않고
> '확인 필요'로 표시합니다."

추가로 아래 내용을 짧게 표시한다.

- 현재 가격은 유료 요금제 시작가 기준
- 일부 연간 결제 / 사용자당 가격 포함
- 사용량 한도와 사용자 수는 v1 판단에 포함하지 않음

## 9. 입력하지 않는 항목

현재 v1에서 아래 항목은 입력으로 받지 않는다.

- 업무 목적
- 월 사용량
- 사용자 수
- 다중 PDF 비교

이유:

현재 데이터로 실제 비교할 수 없기 때문이다.

UI에 비활성 입력칸으로 보여 주지도 않는다.
기능이 있는 것처럼 보이게 만들지 않는다.

## 10. Error / Edge Case

### 예산 미입력

예산을 입력해 달라고 안내한다.

### 예산이 0 이하

0보다 큰 금액을 입력하도록 안내한다.

### 출처 인용 미선택

"출처 인용 필요 여부를 선택해 주세요."라고 안내한다.

### OCR 미선택

"OCR 필요 여부를 선택해 주세요."라고 안내한다.

### 모든 후보가 예산 초과

Compare 화면에서는 판단하지 않는다.
Decision 화면에서
"현재 조건에서 후보 없음"으로 보여 준다.

BuildWise가 사용자의 예산을 자동으로 완화하지 않는다.

## 11. Layout 원칙

Desktop 기준으로 아래 형태를 고려한다.

- 왼쪽: 입력 질문, 도움말
- 오른쪽 또는 하단: 현재 입력 조건 요약

입력 3개를 한 화면에서 모두 볼 수 있어야 한다.

과도한 Step-by-step wizard로 쪼개지 않는다.

이유:

입력 항목이 세 개뿐이므로
한 화면에서 입력하는 편이 더 빠르고 비교하기 쉽다.

## 12. 사용자가 이 화면에서 느껴야 하는 것

- 입력할 것이 많지 않다.
- 왜 이 조건을 묻는지 이해된다.
- 현재 데이터로 확인 가능한 것만 묻고 있다.
- 모르는 내용을 아는 척하지 않는 서비스다.
- 내가 입력한 조건이 결과에 어떻게 반영될지 이해된다.

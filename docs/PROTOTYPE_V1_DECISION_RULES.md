# BuildWise PDF Prototype v1

## 1. v1 사용자 입력

- 월 예산 (USD)
- 출처 인용 필요 여부
- OCR 필요 여부

현재 데이터로 검증할 수 없는 아래 항목은 v1 판단 입력에서 제외한다.

- 업무 목적
- 월 사용량
- 사용자 수
- 다중 PDF 비교

## 2. 데이터 기준

### 월 예산

- `clean.csv`의 `price` 사용
- 유료 요금제 시작 가격
- 일부 값은 연간 결제 기준 월 환산 또는 사용자당 가격일 수 있음
- 화면에 이 한계를 표시해야 함

### 출처 인용

- `citation == Yes`이면 지원 확인
- `citation == No`는 기능 미지원으로 단정하지 않음
- "현재 수집 데이터에서 확인 필요"로 처리

### OCR

- `ocr_raw == "Scanned PDF support"`이면 지원 확인
- 빈칸은 미지원으로 단정하지 않음
- "현재 수집 데이터에서 확인 필요"로 처리

## 3. 조건별 상태

| 상태 | 의미 |
| --- | --- |
| 충족 | 현재 데이터에서 조건 충족이 명확하게 확인됨 |
| 확인 필요 | 현재 데이터만으로 지원 여부를 확인할 수 없음 |
| 예산 초과 | 제품 가격이 사용자 예산보다 높음 |

현재 데이터에는 명확한 기능 미지원 정보가 없으므로,
기능 조건에 대해 "미지원" 상태를 임의로 만들지 않는다.

## 4. v1 판단 결과

### 기존 솔루션 활용 후보 있음

사용자가 요구한 모든 조건을
현재 데이터에서 명확하게 충족하는 후보가 1개 이상 존재한다.

### 기존 솔루션 + 추가 확인 필요

가격 조건은 맞거나 일부 필수 기능은 확인됐지만,
한 개 이상의 필수 기능이 현재 데이터에서 확인되지 않는다.

### 현재 조건에서 후보 없음

입력한 월 예산 이하의 비교 가능한 후보가 하나도 없을 때 사용한다.

이 경우는 기능 부족이나 추가 개발 필요를 의미하지 않는다.
따라서 "추가 개발 검토"로 분류하지 않는다.

화면에서는:

- 현재 예산 조건에서 비교 가능한 후보가 없다는 점
- 예산 조건을 조정해 다시 비교할 수 있다는 점

을 안내한다.

BuildWise가 사용자의 예산을 자동으로 완화하지 않는다.

### 추가 개발 검토

v1에서는 확정 판단하지 않는다.

현재 데이터에서 "확인되지 않음"은
"기능이 존재하지 않음"과 같지 않기 때문이다.

향후 명확한 지원/미지원 및 사용 한도 데이터를 보강한 뒤
이 판단을 활성화할 예정이다.

## 5. 결과 화면에서 반드시 보여 줄 것

- 사용자가 입력한 조건
- 전체 후보 수
- 조건을 모두 충족한 후보 수
- 추가 확인이 필요한 후보 수
- 각 제품의 가격
- 출처 인용 확인 상태
- OCR 확인 상태
- 가격 원문
- `detail_url`
- 데이터 한계 안내

## 6. v1 목적

v1의 목적은 완성된 BuildWise 전체 기능을 구현하는 것이 아니라,

> "사용자의 업무 조건과 구조화된 시장 데이터를 비교해
> 근거가 추적되는 후보 판단을 실제 웹에서 수행할 수 있는가?"

를 검증하는 것이다.

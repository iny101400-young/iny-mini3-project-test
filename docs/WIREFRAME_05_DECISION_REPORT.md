# BuildWise Decision Report Wireframe

## 1. 화면 목적

Decision 화면에서 나온 결과를
실무자가 다시 정리하지 않아도
회의·검토·내부 공유에 바로 사용할 수 있는
최종 의사결정 리포트 형태로 보여 준다.

Decision 화면은 탐색과 비교를 위한 작업 화면이고,
Decision Report는 결과를 읽고 공유하기 위한 정리 화면이다.

핵심 질문:

> "그래서 우리 조건에서 무엇을 확인했고,
> 무엇을 우선 검토하며,
> 무엇을 더 확인해야 하는가?"

이 질문에 한 화면에서 답해야 한다.

## 2. Report Header

상단에 아래 정보를 보여 준다.

- BuildWise Decision Report
- 분석 대상: PDF 문서 검토 AI
- 생성 기준: 사용자가 입력한 현재 조건
- 데이터 수집 시점
- 현재 Prototype v1 범위 안내

중요:

보고서가 시장 전체를 대표하거나
완전한 구매 결정을 대신한다고 표현하지 않는다.

## 3. Executive Summary

가장 먼저 한눈에 보여 줄 내용이다.

### 한 줄 판단

가능한 상태:

- 기존 솔루션 활용 후보 있음
- 기존 솔루션 + 추가 확인 필요
- 현재 조건에서 후보 없음

### Recommended Direction

현재 상황에서의 우선 접근 방향을
2~3문장 이내로 정리한다.

예:

> "현재 입력한 조건을 명확하게 충족하는 후보가 확인됩니다.
> 신규 개발 판단보다 기존 SaaS 검토를 우선하고,
> 도입 전 상세 요금제와 운영 조건을 추가 확인합니다."

중요:

아래처럼 확정적이고 검증되지 않은 표현은 사용하지 않는다.

- "최고"
- "최적"
- "무조건 도입"
- "개발 불필요"

## 4. 입력 조건 요약

사용자가 어떤 조건으로 비교했는지 보여 준다.

예:

| 조건 | 입력값 |
| --- | --- |
| 월 예산 | $10 이하 |
| 출처 인용 | 필요함 |
| OCR | 필요함 |

이 영역은 리포트를 다른 사람이 봐도
판단 기준을 이해할 수 있게 해야 한다.

## 5. 판단 숫자 요약

반드시 보여 줄 값:

- 전체 비교 후보 수
- 예산 내 후보 수
- 모든 필수 조건이 확인된 후보 수
- 추가 확인 필요 후보 수

숫자만 크게 강조하지 않고,
각 숫자가 무엇을 의미하는지 함께 표시한다.

## 6. What We Know / What We Need to Check

리포트의 핵심 영역 중 하나다.

두 영역으로 나눈다.

### 현재 확인된 것

예:

- 예산 범위 내 후보 존재
- Citation 지원이 확인된 후보 존재
- OCR 지원이 확인된 후보 존재

실제 결과에 따라 동적으로 표시한다.

### 추가 확인이 필요한 것

예:

- 사용자 수 과금 조건
- 실제 처리 한도
- 상세 요금제 조건
- 조직 보안 / 데이터 정책
- 목록에서 기능 표시가 없던 항목의 실제 지원 여부

중요:

현재 데이터에 없는 내용을
"문제 있음", "미지원"으로 표현하지 않는다.

반드시 "추가 확인 필요"로 표현한다.

## 7. Candidate Shortlist

Decision 화면의 전체 비교표를
그대로 복사하지 않는다.

리포트에서는
실무자가 우선 검토할 후보를 읽기 쉽게 정리한다.

후보별 표시:

- 제품명
- 가격
- 가격 원문
- Citation 상태
- OCR 상태
- 현재 조건 결과
- 확인 필요 항목
- 원문 출처

현재 v1에서는
임의의 추천 점수나 1위, 2위 순위를 만들지 않는다.

후보는 아래 순서로 묶어 보여 줄 수 있다.

1. 모든 필수 조건이 확인된 후보
2. 추가 확인이 필요한 후보

## 8. Evidence Summary

제목:

- 판단 근거

표시:

- 데이터 출처
- 수집 시점
- 가격 원문
- 기능 확인 기준
- 제품별 `detail_url`
- 데이터 정제 기준

Traceable Decision Data 원칙을 보여 준다.

핵심 메시지:

> "판단 결과뿐 아니라
> 그 판단이 어떤 데이터에서 나왔는지 다시 확인할 수 있습니다."

## 9. Market Context

EDA 결과는
추천 근거가 아니라 현재 표본을 이해하는 참고 정보로 보여 준다.

### 현재 실제 확인된 내용

- 정제 데이터 14개
- $0 이상 $10 미만 후보 8개
- Citation Yes 그룹 평균 8.46 USD
- Citation No 그룹 평균 20.75 USD
- Citation No 그룹 n=4
- 해당 그룹에 49 USD 값 포함

반드시 표시:

> "현재 수집한 표본 기준이며,
> PDF AI 전체 시장을 대표하지 않습니다."

Citation 평균 차이 역시
기능 유무가 가격 차이를 만들었다는 인과관계로 표현하지 않는다.

## 10. Next Action

실무자가 리포트를 본 뒤
바로 실행할 확인 작업을 보여 준다.

예:

1. 조건 충족 후보의 공식 요금제 재확인
2. 사용자 수 과금 조건 확인
3. 실제 처리 한도 확인
4. 조직 보안 / 데이터 정책 적합성 검토
5. 확인 결과를 바탕으로 도입 / 보완 / 개발 검토 진행

중요:

5번은 다음 단계의 의사결정 프로세스를 의미하며,
v1이 추가 개발 필요 여부를 이미 확정했다는 뜻으로 표현하지 않는다.

## 11. Data Limit / Disclaimer

짧고 명확하게 보여 준다.

포함할 내용:

- 현재 Prototype v1은 공개된 가격, Citation, OCR 정보를 기준으로 함
- 가격은 유료 요금제 시작가
- 일부 연간 결제 기준 월 환산 / 사용자당 가격 포함
- 기능 미표시는 미지원으로 단정하지 않음
- 사용량, 사용자 수, 보안 조건은 현재 판단 데이터에 포함되지 않음
- 최종 도입 전 공식 원문 확인 필요

이 영역은 숨기지 않는다.

다만 화면의 가장 중요한 결과보다 먼저 나오지는 않게 한다.

## 12. Report Actions

현재 v1에서 확정할 기능:

- 조건 다시 비교하기
- 후보 원문 보기

아직 확정하지 않을 기능:

- PDF 다운로드
- 이메일 전송
- 저장
- 공유 링크
- 로그인 기반 히스토리

이 기능들은 향후 확장 후보로만 남긴다.

## 13. Layout 원칙

Desktop에서 문서형 레이아웃을 우선한다.

읽는 순서:

1. Executive Summary
2. 입력 조건
3. 판단 숫자 요약
4. 현재 확인된 것 / 추가 확인 필요
5. Candidate Shortlist
6. Evidence Summary
7. Market Context
8. Next Action
9. Data Limit

Decision 화면보다
더 차분하고 정리된 "보고서" 느낌이어야 한다.

과도한 대시보드 카드 형태보다
문서형 정보 위계를 우선한다.

## 14. 사용자가 이 화면에서 느껴야 하는 것

- 결과를 다른 사람에게 바로 보여 줄 수 있다.
- 왜 이런 판단이 나왔는지 설명할 수 있다.
- 확인된 정보와 아직 확인할 정보를 구분할 수 있다.
- 후보 제품을 다시 처음부터 검색할 필요가 적다.
- 다음에 무엇을 확인해야 하는지 알 수 있다.
- AI가 근거 없이 결론을 만들었다는 느낌이 들지 않는다.

## Empty Report State — 현재 조건에서 후보 없음

한 줄 판단이
"현재 조건에서 후보 없음"일 때는
일반 리포트와 동일한 Candidate Shortlist 구조를 억지로 보여 주지 않는다.

### Executive Summary

제목:

> 현재 조건에서 비교 가능한 후보가 없습니다.

설명:

> 현재 입력한 예산 범위에서는
> 비교 가능한 후보가 없습니다.
>
> 이 결과는 기능 부족이나
> 추가 개발 필요를 의미하지 않습니다.

### Candidate Shortlist

표시하지 않는다.

후보가 없는 상태에서
빈 표나 임의의 후보를 보여 주지 않는다.

### What We Know

- 현재 입력한 예산 범위 내 비교 가능한 후보 없음
- 기능 부족 여부는 현재 결과만으로 판단할 수 없음
- 추가 개발 필요 여부도 현재 결과만으로 판단하지 않음

### Next Action

1. 예산 조건 다시 입력
2. 현재 비교 조건 확인
3. 조건 변경 후 다시 비교

현재 조건에서는
"조건 충족 후보의 공식 요금제 재확인" 같은
해당되지 않는 액션은 표시하지 않는다.

### CTA

- 예산 조건 다시 입력하기

중요:

- 사용자의 예산을 자동으로 완화하지 않는다.
- 가장 가까운 가격 후보를 보여 주지 않는다.
- 예산 초과 후보를 대체 추천하지 않는다.
- 기능 부족이나 개발 필요로 해석하지 않는다.
- Candidate Shortlist를 빈 표로 보여 주지 않는다.
